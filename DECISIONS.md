# Почему сделано именно так

Это обоснование текущих решений, а не утверждение, что они подходят любому проекту.
Ориентир — маленький воспроизводимый пример оркестрации, который можно понять целиком.

| Решение и место в коде | Причина | Цена и когда менять |
| --- | --- | --- |
| Python 3.12, pyproject.toml | Простое чтение CSV и хорошая связка с Prefect; одна ветка Python сужает проверяемую среду | Зависит от интерпретатора; Go был бы удобнее для одиночного бинарного файла, но не нужен для урока Prefect |
| Prefect в orchestration.py | Наглядные задачи, зависимости, состояния и retry | Много зависимостей и временный сервер. Для разового подсчёта достаточно вызова функций, как в workshop.preview |
| Предметные правила в core.py | Их можно тестировать и использовать без оркестратора | Нет строгой изоляции файлового кода по отдельным модулям; выносить, когда появятся другие приёмники |
| argparse в __main__.py | Две команды, готовый --help без новой зависимости | Для большого CLI с интерактивным вводом можно выбрать другой инструмент |
| Поздний импорт Prefect | Сначала задаётся локальный профиль; demo и help не поднимают сервер | Нельзя бездумно переносить import наверх, иначе настройки могут примениться слишком поздно |
| Локальный ephemeral сервер | Не нужны аккаунт, Cloud и постоянно запущенная служба | Первый запуск медленнее; для общей команды и расписания нужен отдельный управляемый сервер |
| None для API URL и ключа | Явно выбирает локальный режим; пустая строка ломала EventsWorker 3.8.8 | Это адаптер конкретного учебного режима, а не универсальная конфигурация всех опций Prefect |
| Четыре последовательных шага | Каждое действие имеет наблюдаемую причину отказа | Параллельное исполнение цепочки не ускорит расчёт. Параллелить стоит независимые пакеты |
| Два потока task runner | Достаточно для локальной демонстрации ожидания futures | Нет распределения на другие компьютеры; увеличение числа потоков здесь не добавляет пропускной способности |
| CSV с точным заголовком | Можно открыть и изменить руками, легко воспроизвести ошибку | Контракт чувствителен к порядку полей; для большого набора полезнее типизированный формат вроде Parquet |
| Предельные байты и строки | Держим весь пакет в памяти в известных небольших границах | Не обработаем большой файл; тогда нужны потоковое чтение/батчи и отдельные тесты ресурсов |
| День без времени и одна валюта | Дневной пример обходится без зон и курсов валют | Нельзя складывать разные валюты. Новые currency/event_time требуют контракта, проверки и новой версии смысла |
| Деньги целыми копейками | Суммы и умножение не зависят от двоичного float | Для долей копейки и правил округления может понадобиться Decimal с явно выбранной политикой |
| Маленький whitelist товаров | Видны ошибки и границы входа | Новый товар требует правки кода. Реальный справочник лучше загружать и версионировать отдельно |
| dict для передачи шагов | Мало полей, легко посмотреть в debugger/JSON | Опечатки обнаружатся во время исполнения. При росте схемы полезны dataclass/Pydantic и явная модель версий |
| ID и сравнение всей записи | Различаем точный дубль и противоречие | Нет версии события, поэтому не знаем, какая конфликтующая запись новее. Не выбираем последнюю по месту в CSV |
| Весь пакет отклоняется при ошибке | Неполная выручка не выглядит как полная | Одна строка блокирует все. Для карантина нужны отдельный отчёт потерь и явная отметка неполноты результата |
| SHA-256 от версии и байтов | Ключ воспроизводим и не зависит от времени запуска | Перестановка строк создаёт новый пакет. Семантическая идемпотентность требует канонизации или ключа партии от источника |
| Ключ sales-v1 отдельно от версии приложения | Документальная правка не должна менять результат загрузки | Разработчик обязан обновлять версию смысла, когда меняет формулу/контракт |
| NO_CACHE и persist_result=False | Урок не зависит от внешнего кэша и его срока жизни | При новом запуске расчёт выполняется снова. Сохранять результаты имеет смысл для дорогих шагов с изученной политикой хранения |
| summary, report и manifest | Машинное чтение, просмотр человеком, контроль связи файлов | Три файла усложняют публикацию, зато каждая роль видима. Манифест — не подпись и не шифрование |
| Стабильные байты без timestamp | Повтор можно проверить прямым сравнением | Время запуска хранится в технической истории, а не в неизменяемой сводке |
| Staging рядом с результатом | Готовая папка становится видна после завершения записи и переименования | Нет fsync, блокировок и гарантий питания. Для нескольких писателей нужен транзакционный приёмник или протокол блокировки |
| Проверка существующих байтов | Повтор безопасен, повреждение не маскируется перезаписью | Повреждённый результат требует ручного решения; автоматическое восстановление должно иметь отдельную политику и резервную копию |
| Retry только TransientPublishError | Повтор помогает при временном отказе и не скрывает плохие данные | Настоящие сетевые сбои здесь не классифицируются. Для реального API определить конкретные коды и лимит backoff/jitter |
| retries=2, delay=0.1 | Видно восстановление, урок проходит быстро | Максимум 3 попытки. В рабочей системе задержку выбирают по поведению приёмника и ограничениям запросов |
| unittest и отдельный smoke | Правила проверяются быстро, механизм Prefect проверяется настоящим запуском | Unit-тесты не заменяют интеграцию; smoke требует разрешённых локальных сокетов |
| uv.lock и закреплённый uv | Можно восстановить один набор зависимостей с хэшами | Обновление требует проверки совместимости. Наличие библиотеки в lock не означает запуск сервиса Redis/Docker/PostgreSQL |
| Явный PUBLIC_FILES.txt | В ZIP попадает проверенный набор исходников | Новый нужный файл надо добавить вручную. Фильтр шаблонов не гарантирует отсутствие любого возможного секрета |
| Отдельная лабораторная workspace/learn | Можно портить копии и видеть последствия, сохраняя прежнее демо | Данные не коммитятся; для нового чистого опыта выбери другую --folder |
| VS Code задачи типа process | Аргументы передаются отдельно без сложного экранирования оболочки; Python берётся из .venv проекта | На новом компьютере надо восстановить .venv; CLI остаётся доступен и без редактора |

## Как аргументировать собственное изменение

Для каждой новой функции заполни четыре предложения: «Нужно получить …»;
«Вход гарантирует …»; «Выбираю …, потому что …»; «Проверю примером …, при сбое будет …».
Например, загрузка в PostgreSQL обоснована требованием общей транзакции и конкуренции,
а не тем, что «база солиднее файлов». Добавление currency обосновано реальными
несколькими валютами; одной колонки недостаточно, если продолжить складывать их вместе.

Когда редактируешь свой вариант, допиши сюда решение и проверяемую цену. Если ничего
не меняет наблюдаемое поведение, отдельная платформа обычно пока не нужна.

Официальные источники: [Prefect retries](https://docs.prefect.io/v3/how-to-guides/workflows/retries),
[uv sync](https://docs.astral.sh/uv/concepts/projects/sync/),
[задачи VS Code](https://code.visualstudio.com/docs/debugtest/tasks),
[настройки Python](https://code.visualstudio.com/docs/python/settings-reference).
Конкретные границы гарантий и выбор контрактов выше — решения этого проекта.
