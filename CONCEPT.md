# Концепция: локальная оркестрация продаж

Дата: 19.10.2026, версия 0.1.1. Это учебная работа; коммерческий опыт не заявляется.

Задача: показать, как связать четыре шага обработки и восстановиться после временной
недоступности приёмника. Новый инструмент — Prefect. В предыдущем проекте основным
инструментом был Go; здесь изучаем управление исполнением и границу публикации.

Пользователь запускает генератор, затем конвейер. Получает дневные суммы и проверяемый
манифест. Отдельный флаг воспроизводит сбой первой записи. Повторный запуск не создаёт
новую копию одинакового результата. Плохая строка останавливает весь пакет.

Принятые допущения: один локальный процесс, маленький CSV, фиксированные товары,
календарные даты без часового пояса, одна валюта, один окончательный статус заказа.
Для возвратов, изменения уже загруженных заказов и сверки периодов нужен другой контракт.
Нет реальных имён, адресов, контактов, внешних API или платных сервисов.

Готовность: генератор воспроизводим; суммы проверены вручную и тестами; конфликт ID
отклоняется; точные дубли удаляются; временный отказ записи восстанавливается;
ошибка качества не допускает публикацию; повтор проверяет прежние файлы;
зависимости закреплены; русские инструкции и конспект готовы; архив содержит только
явно разрешённые исходники. Состояние GitHub и CI фиксируется отдельно в VALIDATION.md.

Не входят: интерфейс браузера, развёртывание сервера, планировщик, облако, очередь,
большие данные и гарантии распределённой транзакции. Prefect здесь полезен как
учебный оркестратор; четыре обычные функции были бы проще для разовой обработки.
