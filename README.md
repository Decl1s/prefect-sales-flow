# Оркестрация продаж на Prefect

**Для изучения и редактирования: [начни с карты проекта](START_HERE.md).**
Там порядок чтения кода, запуск из VS Code и отладка по строкам.
[10 практических заданий](EXERCISES.md) и [обоснование решений](DECISIONS.md).

Учебный проект начинающего дата-инженера, 19.10.2026. Локальный конвейер читает CSV,
проверяет заказы, считает дневную выручку и публикует сводку. Prefect задаёт зависимости
шагов и повторяет запись после учебного временного сбоя. Все данные синтетические.

Демонстрация занимает 5–10 минут после установки. Нужны Python 3.12 и uv 0.13.1.
Установка зависимостей требует интернета; обработка работает через временный сервер
на 127.0.0.1 без регистрации, Prefect Cloud и постоянной службы. При выходе сервер останавливается.

## Быстрый запуск

Выполняйте команды в корне этого отдельного проекта. Если uv ещё не установлен,
создайте только локальное окружение для инструмента.

Linux:

```bash
python3.12 -m venv .tools/bootstrap
.tools/bootstrap/bin/python -m pip install uv==0.13.1
.tools/bootstrap/bin/uv sync --frozen --no-dev
.venv/bin/python -m sales_flow demo
.venv/bin/python -m sales_flow run --fail-once
.venv/bin/python -m sales_flow run --fail-once
```

Windows PowerShell:

```powershell
py -3.12 -m venv .tools/bootstrap
.tools/bootstrap/Scripts/python.exe -m pip install uv==0.13.1
.tools/bootstrap/Scripts/uv.exe sync --frozen --no-dev
.venv/Scripts/python.exe -m sales_flow demo
.venv/Scripts/python.exe -m sales_flow run --fail-once
.venv/Scripts/python.exe -m sales_flow run --fail-once
```

Если uv 0.13.1 уже доступен, используйте `uv sync --frozen --no-dev` и пропустите bootstrap.
На Linux Python должен поддерживать venv. Глобальная установка библиотек не нужна.
Первый запуск сервера может занять десятки секунд: Prefect подготавливает локальную SQLite.

Ожидается:

- `demo` создаёт `workspace/input/orders.csv`: 8 строк, 6 уникальных заказов, 2 точных дубля.
- Первый `run --fail-once`: `publish_attempts: 2`, `reused: false`, `revenue_cents: 159000`.
- Второй запуск: `publish_attempts: 1`, `reused: true`, те же байты результатов.
- В `workspace/output/<run_key>/` находятся `summary.json`, `report.md`, `manifest.json`.

`run_key` — SHA-256 версии контракта и исходных байтов. Он одинаков для одинакового входа.
Сводка содержит 5 оплаченных заказов, 1 отменённый; за 01.10 — 36000 копеек,
за 02.10 — 123000 копеек. Дата — календарная дата заказа, валюта учебного примера — рубли.
Числа денег всегда целые копейки.

Повторный `demo` откажется перезаписывать существующий CSV. Для другого набора укажите
`--output workspace/input/another.csv`, затем передайте его через `run --input ...`.
Параметры: `python -m sales_flow run --help`.

## Проверка за несколько минут

Linux; в Windows замените `.venv/bin/python` на `.venv/Scripts/python.exe`:

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python scripts/smoke.py
.venv/bin/python scripts/check_public.py
.venv/bin/python scripts/package_release.py
```

В smoke действительно запускается Prefect: временный отказ даёт 2 попытки записи,
повтор использует прежний результат, плохой CSV блокирует зависимые задачи,
повреждённый результат отклоняется за одну попытку. Завершение — JSON с `smoke: passed`.
Сообщения Prefect об ожидаемых Failed и NotReady в отрицательных сценариях нормальны;
успех проверки определяется кодом выхода 0 и итоговым JSON.

Ручная отрицательная проверка: скопируйте CSV под новым именем, замените `paid` на
`unknown` в одной строке и запустите с отдельным `--output workspace/blocked`.
Ожидается код выхода 1, папка результата не создаётся. Не меняйте исходный набор,
если хотите повторить начальную демонстрацию без пересоздания данных.

## Структура и контракт

`sales_flow/core.py` — контракт и обработка; `orchestration.py` — четыре задачи Prefect;
`local.py` — настройки только текущего процесса; `__main__.py` — команды.
`tests/` проверяет правила и файловые сбои; `scripts/smoke.py` проверяет оркестрацию.

CSV UTF-8 с точным порядком полей:

```text
order_id,order_date,product,quantity,unit_price_cents,status
O0001,2026-10-01,book,2,15000,paid
```

ID: `O` и 4 цифры; дата: корректная `20xx-MM-DD`; product: `book`, `pen`, `bag`;
quantity: 1–9999; unit_price_cents: 1–9999999; status: `paid` или `cancelled`.
Числа без пробелов, знаков, ведущих нулей, дробей и экспонент. LF, CRLF и UTF-8 BOM допустимы.
Пределы: 1 000 000 байт, 10 000 строк. Одна неверная строка блокирует весь пакет.
Совпадающий ID с другими данными считается конфликтом. Пустой набор отклоняется.

## Гарантии и ограничения

Готовый результат сравнивается с ожидаемыми именами и байтами всех трёх файлов.
Повреждение и посторонние файлы требуют ручного решения; программа их не перезаписывает.
Новая сводка сначала записывается во временную соседнюю папку, затем папка переименовывается.
При обычной ошибке временная папка удаляется. После принудительного завершения могут
остаться `.staging-*`; после остановки приложения их можно удалить вручную.

Обработка последовательная по смыслу, хотя зависимости выражены через futures.
Два потока нужны для демонстрации ожидания задач; ускорения этой цепочки не обещаем.
Нет расписания, распределённых workers, защиты от нескольких одновременных писателей,
fsync и гарантии при отключении питания. Все данные пакета помещаются в память.
`retries=2` означает максимум 3 попытки; повторяется только `TransientPublishError`,
а не любая ошибка диска. Это демонстрация политики восстановления.

Prefect хранит техническую историю в `workspace/prefect`; автоматическая аналитика отключена.
CLI изолирует настройки Prefect текущего процесса; пользовательские профили не изменяются.
Используйте синтетические данные. Входы, база Prefect, журналы, окружение, кэш и результаты
исключены из Git и ZIP. Проверка публикации — дополнительный фильтр, а не полный аудит.
