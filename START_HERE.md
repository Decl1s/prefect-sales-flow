# Начни здесь: как читать и менять этот проект

Перед тобой небольшой обработчик продаж, в котором можно проследить весь путь
одного заказа. Сначала изучай расчёт без сервера, затем подключай Prefect и проверяй
сбои. Основные функции снабжены русскими комментариями и docstring: наведи мышь
на имя функции в VS Code или перейди к определению клавишей F12.

## 1. Что уже настроено в IDE

В папке `.vscode` лежат задачи, отладка и выбор локального Python. Они используют
`.venv` именно этого проекта. На текущем компьютере VS Code, Python и debugpy уже
установлены. Новые библиотеки ради комментариев и лабораторной не требуются.
Для запуска на другом компьютере сначала восстанови окружение по README.

Окно серии содержит пять отдельных проектов. Активная учебная папка —
«Сегодня — Prefect: начни с START_HERE». Другие проекты можно открыть и сравнивать,
но команды из этой инструкции выполняются в корне prefect-sales-flow.
В выпадающем списке терминала выбирай эту папку, если VS Code спрашивает рабочую директорию.

Открой меню **Terminal → Run Task** и выбери задачи по номерам:

| Задача | Что происходит | Что увидеть |
| --- | --- | --- |
| 01 — Подготовить учебные CSV | Создаются отдельные синтетические копии | 6 файлов в workspace/learn/input |
| 02 — Посмотреть шаги без Prefect | Чтение → проверка → расчёт в обычном Python | stage_1_read, stage_2_quality, stage_3_summary |
| 03 — Запустить Prefect с учебным сбоем | Полный flow и временный отказ записи | На свежем результате publish_attempts=2 |
| 04 — Посмотреть сводку и отчёт | Чтение готовых файлов для текущего входа | Сумма 159000, таблица двух дней |
| 05 — Повторить загрузку | Тот же flow, проверка прежней папки | reused=true, publish_attempts=1 |
| 06 — Проверить отказ плохих данных | Запуск с unknown вместо paid | Ошибка DataError, новый результат не появляется |
| 07 — Запустить тесты | Проверка правил, файлов и CLI | 19 успешных тестов |
| 08 — Проверить настоящий Prefect | Четыре автоматических сценария | Итоговый JSON smoke=passed |

Задачи не запускаются автоматически при открытии окна. Первая задача сохраняет
уже существующую лабораторную, включая твои правки. Поэтому нажатие 03 второй раз
может сразу показать reused=true: проверенный результат уже существует.
Задача 04 не запускает 03 сама: сначала нужно получить результат, который она читает.
Если редактор показывает Restricted Mode, задачи недоступны до решения о доверии
рабочей папке; это штатный механизм VS Code.

## 2. Карта файлов: что открывать и почему

| Файл | Его ответственность | Когда редактировать |
| --- | --- | --- |

| [sales_flow/core.py](sales_flow/core.py) | Контракт, проверка, дедупликация, суммы, файлы | Меняются товары, поля, формула, отчёт |

| [tests/test_core.py](tests/test_core.py) | Проверки бизнес-правил и файловых сбоев | Добавил правило — добавь проверяемый пример |

| [scripts/smoke.py](scripts/smoke.py) | Реальный Prefect, retry и блокировка зависимостей | Меняется оркестрация |
| [scripts/check_public.py](scripts/check_public.py) | Фильтр явно разрешённых исходников | Меняется состав будущей публикации |
| [scripts/package_release.py](scripts/package_release.py) | ZIP и SHA256SUMS по списку | Меняется упаковка |
| [tests/test_publication.py](tests/test_publication.py) | Проверки фильтра секретов и путей | Меняются правила публикации |
| [PUBLIC_FILES.txt](PUBLIC_FILES.txt) | Явный список публикуемых файлов | Добавил нужный исходник/документ |
| [pyproject.toml](pyproject.toml) | Версия проекта, Python, прямая зависимость | Обоснованно меняешь библиотеку/версию |
| [uv.lock](uv.lock) | Точные версии и хэши всех зависимостей | Обновляет uv; вручную список не редактируй |
| [.github/workflows/ci.yml](.github/workflows/ci.yml) | Удалённые проверки после публикации | Меняются требования к проверкам |

| [.vscode/launch.json](.vscode/launch.json) | Сценарии F5 | Хочешь отлаживать другой вход/этап |
| [.vscode/settings.json](.vscode/settings.json) | Локальный Python и поиск тестов | Нужны настройки редактора для проекта |

`workspace/learn/input` — редактируемые учебные данные. `workspace/learn/output` —
проверенные результаты. `workspace/learn/prefect` — техническая база оркестратора.
`.venv`, `.tools`, `.cache` — восстановимые окружения и кэши. В IDE они скрыты,
чтобы не мешать чтению твоего кода. `artifacts` содержит архивы исходников.
Рабочие данные и окружения не входят в Git и ZIP.

Документы тоже имеют разные роли: README даёт команды, CONCEPT описывает границы,
TECHNOLOGIES перечисляет компоненты, NOTES объясняет понятия, VALIDATION фиксирует
реальные проверки. [DECISIONS.md](DECISIONS.md) объясняет выбор решений и момент,
когда их стоит пересмотреть; [EXERCISES.md](EXERCISES.md) даёт практику.

## 3. Проследи один заказ

В baseline.csv найди O0001. Это две книги по 15000 копеек с paid от 1 октября.
`read_source` читает байты и считает ключ пакета. `quality_gate` превращает количество
и цену в int, а вторую такую же O0001 убирает как дубль. `aggregate` добавляет
2 × 15000 = 30000 к корзине 2026-10-01. O0002 добавляет ещё 6000. Получаем 36000.
`publish` формирует JSON, отчёт Markdown и манифест хэшей, затем сохраняет всю папку.

```text
команда run
  → __main__.main: прочитать аргументы, настроить локальный запуск
  → sales_pipeline: связать четыре задачи
    → read_task → core.read_source
    → quality_task → core.quality_gate
    → aggregate_task → core.aggregate
    → publish_task → core.publish
  → JSON с run_key, reused, publish_attempts, revenue_cents
```

## 4. Пройди код отладчиком

1. Открой `core.py`, найди `group["revenue_cents"] += ...` в aggregate. Нажми
   F9 на этой строке: слева появится красная точка, это точка остановки.
2. В Run and Debug выбери **Учебный разбор: шаги без Prefect** и нажми F5.
   Подготовка CSV выполнится до отладки и сохранит прежние правки.
3. При остановке найди Variables. Раскрой order: ожидай O0001, quantity=2,
   unit_price_cents=15000. Раскрой group: до выполнения строки доход равен 0.
4. Нажми F10 один раз. Теперь revenue_cents равен 30000. Watch может содержать
   `order["order_id"]`, `groups`, `paid`, `cancelled`.
5. F5 продолжает до следующего заказа; F10 выполняет текущую строку; F11 заходит
   внутрь вызванной функции; Shift+F11 выходит из неё; Shift+F5 завершает отладку.

Для дедупликации поставь точку на `if key in unique` в quality_gate и наблюдай unique.
В конце input_rows будет 8, len(unique) — 6, duplicates — 2.
Для ошибки выбери **Разбор конфликта ID без Prefect**. Остановка на raise DataError
покажет старую запись unique[key] с quantity=2 и новую record с quantity=3.
Если нужна автоматическая остановка, включи Raised Exceptions в панели Breakpoints;
после урока выключи, чтобы ожидаемые исключения библиотек не мешали обычной отладке.

Сначала отлаживаем без Prefect, потому что так видно предметное правило без фоновых
потоков и состояния сервера. Затем можно выбрать **Конвейер Prefect: обычный запуск**
и поставить точку в publish_task: get_run_context покажет реальный номер попытки.

## 5. Что означают параметры

| Аргумент | Что передать | Зачем выделен |
| --- | --- | --- |
| run --input | Один CSV | Явно выбираешь пакет и не захватываешь лишние файлы папки |
| run --output | Корневую папку результатов | Внутри автоматически создаётся подпапка run_key |
| run --prefect-home | Папку технической истории | Состояние Prefect отделено от сводок и настроек пользователя |
| run --fail-once | Флаг без значения | Демонстрирует временный отказ первой новой записи |
| demo --output | Имя нового CSV | Генератор не перезаписывает твой файл |
| workshop.py --folder | Папку лабораторной | Можно завести второй чистый набор, сохранив первый |
| workshop.py --case | Имя одного из шести сценариев | Один выбор входа для preview/inspect |

Пример в терминале VS Code на Linux:

```bash
.venv/bin/python scripts/workshop.py prepare
.venv/bin/python scripts/workshop.py preview --case baseline
.venv/bin/python -m sales_flow run --input workspace/learn/input/baseline.csv --output workspace/learn/output --prefect-home workspace/learn/prefect --fail-once
.venv/bin/python scripts/workshop.py inspect
```

Windows: замени `.venv/bin/python` на `.venv/Scripts/python.exe`. Готовые задачи
содержат обе формы. Если команда не видит sales_flow, проверь текущую папку:
в ней должны лежать pyproject.toml и каталог sales_flow.

## 6. Как изменять под свою задачу

Сначала сформулируй одно правило словами: например, «добавить mug», «вычитать скидку»
или «считать по товару». Запиши ожидаемую сумму для 2–3 заказов вручную. Затем найди
изменяемый слой по карте, внеси правку и запусти соответствующий тест.
При изменении смысла расчёта обнови VERSION в core.py: этот ключ участвует в run_key.
Изменение комментария или оформления документа смысла данных не меняет.

Используй небольшие коммиты и просмотр diff. У каждого проекта серии свой Git;
рабочее окно не объединяет их истории. Не нажимай массовый Discard Changes для
возврата учебного опыта: он может стереть нужные правки. Вернуть одну строку можно
через Undo, а данные для нового опыта создать в другой --folder.

Не начинай с uv.lock и внутренностей Prefect: изменение формулы находится в твоём
коротком core.py. Если задача станет большой, аргументы для усложнения уже перечислены
в DECISIONS.md — вместе с ценой каждого решения.
